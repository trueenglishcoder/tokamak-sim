Plasma Boundary Extraction From A Known Equilibrium
====================================================

Scope
-----

This subsystem does not reconstruct an equilibrium from magnetic diagnostics.
It receives a fully known poloidal-flux field psi(R, Z) from the simulator or an
upstream equilibrium system and extracts the physical boundary of the connected
primary plasma core.

The active mode is:

    boundary.mode = "equilibrium_lcfs"

The caller does not select limited or diverted topology. The extractor
classifies it from the field and limiter geometry on every call.

Physical definition
-------------------

The plasma core is the connected family of closed flux surfaces containing the
primary magnetic O-point. Its last closed flux surface is limited by whichever
outward event occurs first:

1. a flux surface contacts the material limiter, or
2. a relevant magnetic saddle produces a separatrix through an X-point.

This yields one of the following topology values:

- limited
- single_null
- double_null
- multi_null

Algorithm
---------

1. Build a bicubic continuous representation of the known grid field. The
   interpolant supplies psi, its gradient, and its Hessian.
2. Generate stationary-point seeds from grid-local gradient minima and cells
   where both gradient components change sign.
3. Refine each seed by damped Newton iterations on grad(psi) = 0.
4. Classify subgrid stationary points by Hessian eigenvalues:
   equal-sign eigenvalues give O-points and opposite-sign eigenvalues give
   X-points.
5. Select the primary O-point from the configured center hint and reject
   unrelated X-points whose axis-to-saddle path leaves the same flux interval.
6. Continuously minimize oriented flux along every limiter segment to generate
   wall-contact candidates.
7. Group relevant X-points by flux level to generate single-, double-, or
   multi-null candidates.
8. Order wall and X-point candidate levels outward from the primary axis.
9. At each candidate level, extract the complete level-set graph with
   contourpy. Project regular points back onto psi = psi_boundary using the
   continuous field.
10. Resolve the connected cycle enclosing the primary O-point and lying inside
    the limiter. X-points are explicit graph nodes. Branches are split at those
    nodes and are not passed through a global smoothing spline.
11. Validate the connected core region, limiter containment, flux residual,
    closure, and critical-point topology.
12. Return the first valid outward candidate as the LCFS.

Limited topology
----------------

A limited boundary is the first core flux surface that contacts the limiter.
Limiter extrema are refined continuously along each limiter segment. The result
stores the contact coordinates and source segment index.

Diverted topology
-----------------

A diverted boundary is the separatrix at a relevant X-point flux. The X-point
is retained as a non-regular node. The core cycle and remaining separatrix
branches are stored independently, so a single smooth tangent is never imposed
through a saddle.

Fixed-angle RL representation
-----------------------------

The dense physical boundary is the source of truth. Fixed-angle radii are a
derived control representation computed only after the dense LCFS exists.

Each center-origin ray is intersected with the dense boundary. A radial
representation is valid only when every ray has exactly one forward
intersection. Missing and multiple intersections are counted and stored.
The implementation never silently chooses one branch and declares a non-star-
shaped boundary valid.

CPU and GPU roles
-----------------

The CPU implementation is an independent reference used for development and
parity tests. It is not executed inside a GPU replay or training step.

The production GPU implementation performs the complete primary-core LCFS
selection. It builds marching-squares segments for each tested level, promotes
selected X-points to graph nodes, traces the cycle containing the primary axis,
and projects fixed-angle radii from that graph. Boundary level, topology, axis,
X-points, contacts, quality metrics, and the optional dense contour therefore
come from one selected GPU result.

Large RL batches disable only dense-contour materialization because the policy
does not consume that array. Single-lane replay enables it for artifacts and
video. This avoids calculating the same boundary a second time on CPU.

Stored artifact channels
------------------------

- boundary_separatrix_branches
- boundary_fixed_angle_valid
- boundary_fixed_angle_counts
- boundary_quality

The six boundary_quality columns are, in order:

1. maximum flux residual
2. normalized flux residual
3. closure error
4. minimum regular gradient magnitude
5. limiter violation count
6. connected core component size

Batched GPU execution
---------------------

The batched GPU path orders limiter and X-point candidates outward from the
magnetic axis. Each tested candidate is converted to a marching-squares segment
graph. A candidate is accepted only when the graph surrounds the primary axis,
remains inside the limiter, and reaches its defining limiter contact or X-point.
The first valid outward candidate becomes the LCFS.

Configured-angle radii are projected from the accepted graph. Artifact runs also
trace the graph cycle, choose the branches directed toward the primary axis at
X-points, resample that ordered cycle, and snap exact X-points and limiter
contacts into it. The contour is not reconstructed from the 32 radii and is not
smoothed by a spline.

CPU/GPU parity tests require equal topology, boundary level within tolerance,
fixed-angle radii within grid-scale error, and bidirectional dense-contour error
within approximately one grid cell. The CPU path is therefore a test oracle,
not a second runtime boundary calculation.

Failure behavior
----------------

The extractor does not invent a circle, reuse a previous contour, smooth sparse
radii into a replacement boundary, or accept the largest available polygon as
a fallback. If no candidate forms a physical boundary of the primary core, the
call fails with an explicit reason and the run handles boundary loss as a
physical stop condition.

Removed mode
------------

suchkov_spline_contour was removed. It sampled a known level set on fixed rays
and replaced it with a periodic cubic spline. That curve was not guaranteed to
remain on the chosen psi level and could smooth away X-point topology. Configs
using that name fail with a migration message instead of silently selecting a
new algorithm.
